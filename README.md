# PAG-Health-LLM

**A Domain-Specific Retrieval-Augmented Large Language Model for Pediatric and Adolescent Gynecology Clinical Decision Support**

Vahid Monfared, Reza Rawassizadeh  
Boston University

## Overview

PAG-Health-LLM is a 7-billion-parameter domain-specialized language model purpose-built for pediatric and adolescent gynecology (PAG). It combines:

- **QLoRA parameter-efficient fine-tuning** of Mistral-7B-Instruct-v0.3
- **Retrieval-augmented generation (RAG)** with BGE embeddings and FAISS
- **Cascading "RAG-first, model-fallback" inference** for safety
- **Citation-grounded outputs** that point to the source paragraph

In published benchmarks on 182 held-out clinical questions, PAG-Health-LLM outperformed three frontier generalists (GPT-4o-mini, LLaMA-3.3-70B, Qwen-3-32B) across eight reference-based metrics (BERTScore 0.909, ROUGE-L 0.413, METEOR 0.526; all *p* < 0.001; Cohen's *d* = 0.46–1.70).

## Quick start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Provide your source corpus

Place plain-text files (one file per section) into `data/source_text/`. Create a question/answer/section_id JSONL at `data/qa_seed.jsonl`:

```json
{"section_id": "section_001", "question": "...", "answer": "..."}
```

### 3. Run the pipeline

```bash
# Stage 1 — chunk the corpus
python pag_health_llm_pipeline.py 1

# Stage 2 — build no-leakage train/val/test splits (70/15/15 by section)
python pag_health_llm_pipeline.py 2 --qa_seed data/qa_seed.jsonl

# Stage 3 — QLoRA fine-tune Mistral-7B (≈30 min on a 16 GB GPU)
python pag_health_llm_pipeline.py 3

# Stage 4 — build the BGE + FAISS retrieval index
python pag_health_llm_pipeline.py 4

# Stage 5 — ask a question
python pag_health_llm_pipeline.py 5 --query "How is PCOS diagnosed in adolescents?"

# Stage 6 — evaluate predictions on the held-out test set
python pag_health_llm_pipeline.py 6 --preds results/test_predictions.jsonl \
                                    --refs  data/qa_test.jsonl
```

### 4. Run the Gradio demo

```bash
export GROQ_API_KEY="your_key_here"
python app.py
```

The Gradio interface listens on `http://localhost:7860`.

## Evaluation metrics

PAG-Health-LLM was evaluated on 10 complementary axes:

| Type | Metrics |
|---|---|
| Lexical overlap | ROUGE-1, ROUGE-2, ROUGE-L, BLEU |
| Character-level fidelity | chrF++ |
| Token-level paraphrase | METEOR |
| Contextual embedding | BERTScore |
| Learned semantic | BLEURT, SAS |
| LLM-as-judge | G-Eval (open-weight judge) |

Statistical analysis uses paired t-tests (n = 182) and Cohen's *d* effect sizes.

## Inference behavior

The system uses a cascading "RAG-first, model-fallback" strategy:

- If the top retrieved passage has cosine similarity ≥ 0.50, the model produces a citation-grounded answer based on retrieved content.
- Otherwise, the system falls back to the base language model and discloses this in the source line.

All responses end with one clean source line:

- `Source: Domain-specific fine-tuned RAG model based on the reference textbook.`  
  *— or —*  
- `Source: Base language model: Mistral-7B-Instruct-v0.3.`

No inline chapter references, section numbers, or source identifiers appear in the answer body.

## Hardware

- Fine-tuning: single NVIDIA T4 or RTX 3060 (≥ 16 GB VRAM), ~30 minutes
- Inference: CPU-only retrieval + Groq API for the base/RAG LLM, or fully local on a 16 GB GPU
